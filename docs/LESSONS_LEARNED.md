# ShrinkCart 开发经验记录

本文记录 ShrinkCart 从 0.2.x 到 0.3.1 开发过程中真实踩过的坑：现象、根因、怎么发现的、以后怎么避免。
通用规则已经写进 [REPO_Mod_Development_Guidelines.md](REPO_Mod_Development_Guidelines.md)，这里保留具体案例，方便以后遇到类似问题时对照。

## 1. 配置与迁移

### 1.1 迁移"执行了"，但什么也没做（0.2.51–0.2.52 速度慢 10 倍）

- **现象**：0.2.51 把缩放速度改成 ×10 刻度存储，老玩家更新后缩放动画慢了 10 倍。
- **根因**：迁移代码在绑定配置**之前**用 `TryGetEntry` 读旧值。插件 `Awake` 时，文件里的值都还在 BepInEx 的孤儿条目里，而 `TryGetEntry` 只查已绑定的条目，所以永远读不到。代码却照样写下了"已迁移"标记，此后再也不会重试。
- **怎么发现的**：对照 BepInEx 的实现，用真实旧配置写复现程序。
- **对策**（规范 §8）：
  - 用公开 API 读取原始值：先用哨兵默认值 `Bind<string>` 读出原文，再 `Remove`；
  - 在第一次绑定前记录 cfg 是否存在，以此区分首次安装和升级；
  - 迁移版本号存在 cfg 里；
  - 每个迁移都用真实历史配置样本做测试。

### 1.2 改了默认值，老玩家不会跟着变

- **现象**：v0.2.2–v0.2.8 安装的玩家，「离车防抖延迟」一直是 2.5 秒，新玩家是 0.5 秒；早期的分类倍率、敌人球倍率也偏小。
- **根因**：BepInEx 只在配置项不存在时写入默认值。已经写进 cfg 的值，不会随新版本的默认值变化。
- **怎么发现的**：逐个历史版本提取每个配置项的默认值，对比变化。
- **对策**（规范 §8）：
  - 改默认值时，先评估已有配置会怎样；
  - 需要统一时写一次性迁移，只升级"仍等于某个历史默认值"的值；
  - 玩家改过的值不动，开关类不动。

### 1.3 改名不迁移，旧值永远残留

- **现象**：v0.2.2 把分组「Tiny 小型贵重物」改名为「Tiny 微型贵重物」，没有写迁移。老配置里的旧分组一直留到 0.2.52，里面的值早已不生效。
- **对策**：
  - 键名是公共接口，改名必须登记旧键继承；
  - 发布前用历史版本源码扫描所有用过的键名，确认每个旧键都被继承或清理。

### 1.4 状态放在 cfg 之外会丢

- **现象**：「启用重量随缩放降低」被强制改回开启。
- **根因**：0.2.39 在配置目录里放了一个 marker 文件，用来记录"迁移过没有"。新建或导入 profile 时这个文件不存在，玩家关掉的设置就会被覆盖。
- **对策**：迁移状态只放在 cfg 里，作为对 REPOConfig 隐藏的条目。

### 1.5 滑条的浮点误差

- **现象**：REPOConfig 滑条会写出 `0.3999999` 这类值，积累之后菜单的精度推断出错。0.2.52 的规整用 `Approximately` 比较，放过了 `4.999997` 这种小误差。
- **对策**：读取和写入时都规整到两位小数，并用精确比较。

## 2. 游戏行为

### 2.1 游戏会复用对象实例

- **现象**：同一个敌人死亡重生后，再进车不会被秒杀。
- **根因**：敌人重生复用同一个实例（`EnemyHealth.OnSpawn` 会重置血量和 `dead`），而按实例 ID 记录的"已处决"集合每关才清一次。
- **对策**：用 1 秒的短冷却防止重复伤害；是否已死亡、剩余血量这类状态，用的时候现查。

### 2.2 高频 hook

- **调用频率**：
  - `PhysGrabCart.ObjectsInCart` 每帧、每辆车都会被调用；但原版只在 12 m 内有玩家、并且计时器到期时才真正扫描，大约每 0.5 秒一次。
  - `PhysGrabInCart.Add` 来自 `OnTriggerStay`，每个物理帧、每个未休眠的物体都会调用一次。
- **旧做法**：0.2.x 在这两个地方每帧做组件查找、字符串处理和反射。
- **现在的做法**：
  - 分类结果按实例缓存；
  - 只在计时器被重置时处理扫描结果，计时器重置就说明原版刚完成一次真实扫描；
  - Prefix 与 Postfix 之间用 `__state` 传递信息。
- **补充**：休眠的刚体不会触发 `OnTriggerStay`。车里静止的物品主要靠原版扫描确认还在车内。

### 2.3 重构时，手感也是需求

- **现象**：0.3.x 早期设计的离车恢复，要多等一个维护间隔，物品多时最多多等 1 秒，和 0.2.52 的手感不一致。
- **怎么发现的**：逐行读旧代码，推算旧版的恢复时刻：旧版每帧刷新到期时刻，到期立即恢复。
- **对策**：重构前把时序和手感列为需要与旧版对照的行为，并用测试固定下来（`PresenceTracker.HasDue` 的用例）。

## 3. 依赖库

### 3.1 不要长期改写依赖库的全局开关

- **现象**：ScalerCore 的 `AllowDeadHeads` 是全局静态开关。0.2.x 在头颅功能开启期间一直把它设为 `true`，导致缩小枪等其他使用者也能缩小头颅。
- **对策**：
  - 只在缩小头颅的那一次调用中临时打开，在 `finally` 里还原；
  - 前提是已经核实 `ApplyIfNotScaled` 是同步调用，并且只有 `DispatchShrink` 读取这个开关；
  - 依赖升级时重新核对这两点。

### 3.2 只恢复自己施加的缩放

- **现象**：0.2.x 用"缩放参数长得像 ShrinkCart 的"来认领已有的缩放，参数碰巧一致时会接管别人的缩放。
- **对策**：显式记录所有权（目标、种类、倍率），恢复前核对倍率是否仍然一致。ScalerCore 只在 `Factor ≤ 0` 时替换倍率，所以倍率会原样保留，可以用来核对。

## 4. 构建与工具链

### 4.1 手写的校验清单会过时

- **现象**：旧 `build.ps1` 手写了要检查的方法和字段，逐渐和代码脱节：有不再使用的，也漏了新用到的，而且只比较参数个数。
- **现在**：构建期校验全部从编译产物推导。第一次运行就抓到一处功能代码越过网关、直接读取 ScalerCore 的全局开关。

### 4.2 publicize 在 Unity Mono 上可用的前提

- 直接访问游戏的 internal / private 字段，依赖两样东西：
  - 开启 `AllowUnsafeBlocks` 后，编译器写入的 `SecurityPermission(SkipVerification = true)`，Mono 据此跳过访问检查；
  - `IgnoresAccessChecksTo`。

  去掉 `AllowUnsafeBlocks`，运行时会报 `FieldAccessException`。
- **游戏内验证方法**：开启调试日志，看 `scansProcessed` 计数是否在增长。每次扫描都会读取 private 字段 `objectInCartCheckTimer`。

### 4.3 Windows PowerShell 5.1 的编码

- **脚本读取**：没有 BOM 的 `.ps1` 会按系统 ANSI 代码页读取，中文注释可能吞掉换行、改变脚本含义。所以 `build.ps1` 只用 ASCII；需要中文的脚本，存成带 BOM 的 UTF-8。
- **子进程输出**：按 OEM 代码页解码。所以构建工具的控制台输出只用英文；需要读取 UTF-8 输出时，先设置 `[Console]::OutputEncoding`。
- **命名冲突**：`cat` 是 `Get-Content` 的别名，自定义函数不要叫 `Cat`。

### 4.4 测试进程加载 BepInEx

- `BepInEx.Core` NuGet 包里的 `SkipBepinRefs` 目标会把 BepInEx.dll 从输出目录移除（插件运行时由 BepInEx 宿主提供），测试项目要自己加回来。
- Unity 程序集引用的是强签名的 netstandard 2.1，而 .NET Framework 自带的是 2.0。测试输出目录需要复制一份游戏自带的 `netstandard.dll`。

### 4.5 依赖来自哪个 profile

- **现象**：本机不同 r2modman profile 里的依赖版本不一样，旧 profile 里是 ScalerCore 0.6.1。旧脚本默认读取名为 `REPO` 的 profile，稍不注意就会编译进旧版依赖。
- **对策**：profile 路径写在本机 props 里；依赖只从该 profile 的 `<Team>-<Package>` 目录解析，并校验版本。

## 5. 测试与排障

- **日志会被覆盖**：Unity 只保留最近两次会话的 `Player.log` 和 `Player-prev.log`，BepInEx 的 `LogOutput.log` 只保留当前一次。多启动几次，重要那一局的日志就没了。测试完先把日志存下来，或者在 `BepInEx.cfg` 中设置 `[Logging.Disk] AppendLog = true`。
- **r2modman**：`mods.yml` 才是 profile 安装状态的依据，`cache` 目录里有文件不代表已经安装。`build.ps1 -InstallToProfile` 只复制文件，r2modman 界面上的版本号不会更新。
- **联机**：ShrinkCart 不发送任何网络消息，决策只在主机上做，结果由 ScalerCore 和游戏同步。所以混装不同版本时，效果由主机的版本决定。
